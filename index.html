Auticket

Municipal enforcement system · GovTech

Parking enforcement in Israel runs on a broken chain: the officer writes a ticket, the citizen gets paper, payment lives elsewhere and appeals disappear. Auticket puts the whole chain in one system - four apps, one design language - and adds a vision layer that turns cameras a city already owns into enforcement.

RabbiList

Torah video platform · Community

A kosher video library joined to a live schedule of in‑person classes, searchable country › city › neighbourhood. The decision that shaped everything: the home page is a location form, not a video feed - because the real need is physical. A physical class is an event with a place, a time and a registration, so it got its own data model rather than being squeezed into a video.

About

Design and code
are the same job.

I don't hand a spec off and I don't hand a design off. I define the product, draw the interface, model the data behind it, and write the code that makes it real - so the decisions hold up all the way down.

That shows up in small places. In Auticket the appeal button sits beside the pay button instead of buried three screens deep, because a citizen who can't find it calls the municipality. In RabbiList a physical class is a separate entity from a video, because forcing it into the video model would have broken search. In CyRook every screen opens by explaining itself, because the audience is developers, not security engineers.

I work in Hebrew and English, right‑to‑left and left‑to‑right, on the web and on native mobile.
